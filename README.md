# מקצר קישורים סטטי (GitHub Pages)

## הקבצים
- `links.json` — מסד הנתונים.
- `404.html` — מבצע את ההפניה בפועל.
- `admin.html` — ממשק ניהול הקישורים.
- `index.html` — דף בית כללי (נגיש בלי כינוי).
- `style.css` — עיצוב אחיד לכל הדפים (ערכת נושא כהה ומעוגלת).
- `favicon.svg`, `favicon.ico`, `apple-touch-icon.png` — אייקון האתר.

## איך זה עובד
- `links.json` — **ה-כינוי הוא המפתח (key) של כל רשומה, לא שדה בתוכה** -
  כלומר `"promo"` בדוגמה הבאה הוא הכינוי שיופיע ב-URL:
  ```json
  {
    "promo": {
      "url": "https://target.com",
      "created": "2026-07-29T10:00:00Z",
      "maxClicks": 20,
      "passwordHash": null
    }
  }
  ```
  `maxClicks` ו-`passwordHash` הם `null` אם לא רלוונטיים. הקוד ניגש
  לרשומה לפי `links[הכינוי]` - כלומר "האובייקט שהמפתח שלו שווה לכינוי
  שבכתובת".
- `404.html` — GitHub Pages מגיש אותו לכל כתובת שלא קיימת בריפו. הוא בודק
  אם הקישור פג תוקף (הגיע למספר הכניסות המותר), מבקש סיסמה אם צריך,
  סופר קליק, ומפנה ליעד.
- `admin.html` — ממשק ניהול: הוספה/עריכה/מחיקה, הצגת תאריך יצירה, הגבלת
  קליקים, מצב הגנת סיסמה, מספר קליקים נוכחי, וכפתור העתקת הקישור
  המקוצר ללוח.
- `index.html` — דף הבית שמוצג בכניסה לכתובת הריפו בלי כינוי.

כתובת קישור תיראה כך: `https://sh770.github.io/links/כינוי`

## הגבלת תוקף לפי כניסות
בשדה "הגבלה" בעמודת הניהול אפשר להזין מספר כניסות מקסימלי. `404.html`
בודק את הספירה הנוכחית לפני ההפנייה - אם הגיע למגבלה, יוצג "פג תוקף"
במקום הפניה. שדה ריק = ללא הגבלה.

## קישור מוגן בסיסמה
בעמודת "סיסמה" אפשר להזין סיסמה חדשה לכל קישור (כדי להחליף/להוסיף), או
ללחוץ "הסר" כדי לבטל את ההגנה לגמרי. הסיסמה **לא** נשמרת כטקסט גלוי -
נשמר רק hash (SHA-256) שלה בתוך `links.json`. `404.html` מבקש סיסמה
מהמבקר ומשווה את ה-hash לפני ההפניה.

**חשוב להבין את המגבלה:** מכיוון שה-hash עצמו נמצא בקובץ ציבורי
(`links.json`), מדובר בהגנה "רכה" מפני מבקר אקראי - לא הגנת אבטחה
אמיתית. אדם עם ידע טכני שמוריד את ה-hash יכול לנסות לפצח אותו
בלי-לחיבור (offline). אל תשתמש בזה להגנה על תוכן רגיש באמת.

## ספירת קליקים
הספירה מתבצעת דרך שירות חיצוני חינמי וללא הרשמה
([countapi.mileshilliard.com](https://countapi.mileshilliard.com/)) - הכתובת
404.html שולחת "hit" עם מפתח ייחודי לכל כינוי, ו-admin.html שולף את הערך
להצגה בלבד. חשוב:
- המפתחות בשירות הזה **ציבוריים** - כל מי שמנחש/רואה את המפתח יכול לראות
  את המספר (אך לא לשנות יעדים - זה נשלט רק דרך GitHub). לכן יש קידומת
  (`COUNTER_PREFIX`) שצריך לשנות לערך ייחודי משלך.
- יש לוודא ש-`COUNTER_PREFIX` **זהה** בדיוק בקובץ `404.html` ובקובץ
  `admin.html`, אחרת המספרים לא יתאימו.
- זה שירות צד שלישי חינמי - אין התחייבות לזמינות לאורך זמן. אם ירצה
  להחליף אותו בעתיד, צריך רק לעדכן את שתי הכתובות בקוד.

## שינוי כינוי לקישור קיים
בפרטי הקישור (אחרי הלחיצה עליו) יש שדה "כינוי" בראש הרשימה - שינוי הערך
שבו וקליק מחוץ לשדה משנה את הכינוי (בפועל: יוצר מפתח חדש ב-JSON עם אותם
פרטים, ומוחק את הישן). **חשוב לשים לב לשתי תופעות לוואי:**
- כל קישור ישן/QR ששותף עם הכינוי הקודם **יפסיק לעבוד** - הוא לא יופנה
  אוטומטית לחדש.
- ספירת הקליקים מתאפסת, כי היא נשמרת לפי הכינוי (הספירה החיצונית קשורה
  למחרוזת הכינוי עצמה, לא לרשומה).
- אם תבחר כינוי שכבר תפוס, השינוי לא יתבצע ותופיע הודעה.

## העתקת קישור
ברשימת הניהול, לחיצה על קישור פותחת פרטים ובהם כפתור "העתק קישור" שמעתיק ללוח את
הכתובת המלאה (`https://sh770.github.io/links/<כינוי>`), כדי שיהיה נוח
לשתף אותה.

## קוד QR
לצד כפתור ההעתקה יש כפתור "QR" שמציג ברשומה עצמה תמונת קוד QR לקישור
המקוצר, כדי שאפשר יהיה לסרוק אותו ישירות (למשל מפלייר או מסך). התמונה
נוצרת דרך שירות חיצוני חינמי וללא הרשמה
([api.qrserver.com](https://goqr.me/api/)) - לא נשמר שום דבר, רק תמונה
שנטענת לפי דרישה בלחיצה.

## זמן עדכון
אחרי שמירה ב-admin.html, ייתכן שיעברו דקה-שתיים עד שהשינוי יופיע בפועל
בכתובת הציבורית - זהו זמן הפריסה (deploy) הרגיל של GitHub Pages, לא
תקלה. הממשק מציג הודעה על כך אחרי כל שמירה.

## תכונה עתידית: הגבלה לפי מדינה
נשקלה תכונה שמגבילה קישור למדינות מסוימות בלבד (לפי זיהוי IP), אך היא
הוסרה בינתיים. אם תתווסף בעתיד, עדיף שתהיה עם תפריט בחירת מדינות
(checkbox / multi-select) ולא הקלדת קודים ידנית.

## הקמה
הקבצים כבר מוגדרים עבור `sh770/links` - אין צריך לערוך שום דבר בקוד.

1. צור ריפו בשם `links` תחת החשבון `sh770` והעלה אליו את כל הקבצים
   (`links.json`, `404.html`, `admin.html`, `index.html`, `style.css`,
   `favicon.svg`, `favicon.ico`, `apple-touch-icon.png`).
2. הפעל GitHub Pages: Settings → Pages → Source: `main` branch, `/ (root)`.
3. זהו.

אם בעתיד תשנה את שם הריפו או תעביר לחשבון אחר, יש לעדכן שלושה מקומות:
- ב-`404.html`: `REPO_BASE`
- ב-`admin.html`: `OWNER` ו-`REPO`
- אופציונלי: `COUNTER_PREFIX` (זהה בשני הקבצים) - לא חובה לשנות, אבל אם
  אתה פותח ריפו נוסף מאותה תבנית, כדאי קידומת שונה לכל ריפו.

## יצירת טוקן לניהול
כדי לנהל קישורים דרך `admin.html` צריך GitHub Personal Access Token עם
הרשאת כתיבה **לריפו הזה בלבד**:

1. GitHub → Settings → Developer settings → Personal access tokens →
   Fine-grained tokens → Generate new token.
2. **Token name** - שדה שם חופשי, רק לזיהוי שלך ברשימת הטוקנים - לא
   משפיע על אופן הפעולה. מומלץ שם ברור כמו `links-admin`, כדי שתדע
   בעתיד למה הטוקן הזה משמש אם תרצה למחוק או לחדש אותו.
3. Repository access: **Only select repositories** → בחר את הריפו הזה.
4. Permissions → Contents: **Read and write**.
5. צור את הטוקן ושמור אותו במקום בטוח (הוא מוצג פעם אחת בלבד).

## חשוב לגבי אבטחה
כל הקבצים בריפו (כולל קוד ה-HTML/JS) גלויים לציבור, גם אם תשתמש בסיסמה
בתוך הקוד — היא תהיה גלויה לכל מי שיסתכל ב-source. **לכן אין להטמיע את
הטוקן בקוד עצמו.** הדרך הבטוחה: להיכנס ל-`admin.html` ולהזין את הטוקן
ידנית בכל פעם (או פעם אחת — הוא נשמר רק ב-localStorage בדפדפן שלך, לא
נכתב לריפו). בלי טוקן תקין עם הרשאת כתיבה, GitHub עצמו יחסום כל ניסיון
עדכון — זו ההגנה האמיתית.

אם ברצונך רמת אבטחה גבוהה יותר (למשל שגם הצפייה בקישורים תהיה מוגנת),
זה דורש שרת אמיתי — הפתרון הזה מתאים לתרחיש של "רק אני יודע/ת את
הטוקן ומנהל/ת קישורים".

### לגבי קובץ `.env`
שים לב: הפרויקט הזה **לא** משתמש בקובץ `.env` בפועל, ולא יכול - זהו
אתר סטטי טהור בלי שלב build (npm/webpack/vite וכדומה), שרק דרכו קובץ
`.env` היה יכול "להיכנס" לקוד ה-JS שרץ בדפדפן. גם אם תיצור קובץ `.env`
ותוסיף אותו ל-`.gitignore` - הדפדפן פשוט לא יכול לקרוא אותו, ובכל מקרה
`.gitignore` מונע ממנו להיות חלק מהריפו שמפורסם ב-GitHub Pages. הגדרת
`.gitignore` בכללי היא הרגל טוב, אבל בפרויקט הספציפי הזה היא לא נחוצה
בשביל הטוקן - השיטה שכבר מיושמת (הזנת הטוקן ב-`admin.html`, שנשמר רק
ב-localStorage של הדפדפן) היא הדרך הנכונה כאן.

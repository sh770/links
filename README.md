# מקצר קישורים סטטי (GitHub Pages)

## הקבצים
- `links.json` — מסד הנתונים.
- `404.html` — מבצע את ההפניה בפועל.
- `admin.html` — ממשק ניהול הקישורים.
- `index.html` — דף בית כללי (נגיש בלי כינוי), כולל קטלוג ציבורי לצפייה
  בכל הקישורים משולב בתוכו (ראה סעיף ייעודי למטה) - **גישה פתוחה לכל
  אחד, בלי טוקן**, וקישור עליון לדף הניהול.
- `style.css` — עיצוב אחיד לכל הדפים (ערכת נושא כהה ומעוגלת).
- `favicon.svg`, `favicon.ico`, `apple-touch-icon.png` — אייקון האתר.

## איך זה עובד
- `links.json` — **ה-כינוי הוא המפתח (key) של כל רשומה, לא שדה בתוכה** -
  כלומר `"promo"` בדוגמה הבאה הוא הכינוי שיופיע ב-URL:
  ```json
  {
    "promo": {
      "url": "https://target.com",
      "created": "2026-07-29T10:00:00Z",
      "maxClicks": 20,
      "passwordHash": null
    }
  }
  ```
  `maxClicks` ו-`passwordHash` הם `null` אם לא רלוונטיים. הקוד ניגש
  לרשומה לפי `links[הכינוי]` - כלומר "האובייקט שהמפתח שלו שווה לכינוי
  שבכתובת".
- `404.html` — GitHub Pages מגיש אותו לכל כתובת שלא קיימת בריפו. הוא בודק
  אם הקישור פג תוקף (הגיע למספר הכניסות המותר), מבקש סיסמה אם צריך,
  סופר קליק, ומפנה ליעד. **בקישור תקין ולא מוגן ההפניה שקטה לגמרי -
  בלי שום הודעה או ספינר** - המבקר פשוט מגיע ליעד. הודעה מוצגת רק
  כשמשהו לא רגיל: סיסמה נדרשת, הכינוי לא נמצא, או שהקישור פג תוקף.
- `admin.html` — ממשק ניהול: הוספה/עריכה/מחיקה, הצגת תאריך יצירה, הגבלת
  קליקים, מצב הגנת סיסמה, מספר קליקים נוכחי, וכפתור העתקת הקישור
  המקוצר ללוח.
- `index.html` — דף הבית שמוצג בכניסה לכתובת הריפו בלי כינוי. כולל
  קישור עליון לדף הניהול, ומתחתיו הקטלוג הציבורי המלא (ראה סעיף
  "קטלוג ציבורי" למטה).

כתובת קישור תיראה כך: `https://sh770.github.io/links/כינוי`

## הגבלת תוקף לפי כניסות
בשדה "הגבלה" בעמודת הניהול אפשר להזין מספר כניסות מקסימלי. `404.html`
בודק את הספירה הנוכחית לפני ההפנייה - אם הגיע למגבלה, יוצג "פג תוקף"
במקום הפניה. שדה ריק = ללא הגבלה.

## קישור מוגן בסיסמה
בעמודת "סיסמה" אפשר להזין סיסמה חדשה לכל קישור (כדי להחליף/להוסיף), או
ללחוץ "הסר" כדי לבטל את ההגנה לגמרי. הסיסמה **לא** נשמרת כטקסט גלוי -
נשמר רק hash (SHA-256) שלה בתוך `links.json`. `404.html` מבקש סיסמה
מהמבקר ומשווה את ה-hash לפני ההפניה.

**חשוב להבין את המגבלה:** מכיוון שה-hash עצמו נמצא בקובץ ציבורי
(`links.json`), מדובר בהגנה "רכה" מפני מבקר אקראי - לא הגנת אבטחה
אמיתית. אדם עם ידע טכני שמוריד את ה-hash יכול לנסות לפצח אותו
בלי-לחיבור (offline). אל תשתמש בזה להגנה על תוכן רגיש באמת.

## ספירת קליקים
הספירה מתבצעת דרך שירות חיצוני חינמי וללא הרשמה
([countapi.mileshilliard.com](https://countapi.mileshilliard.com/)) - הכתובת
404.html שולחת "hit" עם מפתח ייחודי לכל כינוי, ו-admin.html שולף את הערך
להצגה בלבד. חשוב:
- המפתחות בשירות הזה **ציבוריים** - כל מי שמנחש/רואה את המפתח יכול לראות
  את המספר (אך לא לשנות יעדים - זה נשלט רק דרך GitHub). לכן יש קידומת
  (`COUNTER_PREFIX`) שצריך לשנות לערך ייחודי משלך.
- יש לוודא ש-`COUNTER_PREFIX` **זהה** בדיוק בקובץ `404.html` ובקובץ
  `admin.html`, אחרת המספרים לא יתאימו.
- זה שירות צד שלישי חינמי - אין התחייבות לזמינות לאורך זמן. אם ירצה
  להחליף אותו בעתיד, צריך רק לעדכן את שתי הכתובות בקוד.

## שינוי כינוי לקישור קיים
בפרטי הקישור (אחרי הלחיצה עליו) יש שדה "כינוי" בראש הרשימה - שינוי הערך
שבו וקליק מחוץ לשדה משנה את הכינוי (בפועל: יוצר מפתח חדש ב-JSON עם אותם
פרטים, ומוחק את הישן). **חשוב לשים לב לשתי תופעות לוואי:**
- כל קישור ישן/QR ששותף עם הכינוי הקודם **יפסיק לעבוד** - הוא לא יופנה
  אוטומטית לחדש.
- ספירת הקליקים מתאפסת, כי היא נשמרת לפי הכינוי (הספירה החיצונית קשורה
  למחרוזת הכינוי עצמה, לא לרשומה).
- אם תבחר כינוי שכבר תפוס, השינוי לא יתבצע ותופיע הודעה.
- שלושה כינויים חסומים תמיד: `admin`, `index`, `404` - כי GitHub Pages
  פותר כתובת בלי סיומת (כמו `/admin`) ישירות לקובץ ה-HTML המתאים, ולא
  היה מגיע בכלל למנגנון ההפניה שלנו.

## קישורים פנימיים בלי סיומת .html
GitHub Pages פותר אוטומטית כתובת בלי סיומת (`/admin`) לקובץ ה-HTML
המתאים (`admin.html`) - לכן הקישור מ-`index.html` לדף הניהול הוא
`href="admin"` ולא `href="admin.html"`. זו התנהגות מובנית של GitHub
Pages (לא של הקוד שלנו) שלא קיימת למשל ב-GitLab Pages.

## העתקת קישור
ברשימת הניהול, לחיצה על קישור פותחת פרטים ובהם כפתור "העתק קישור" שמעתיק ללוח את
הכתובת המלאה (`https://sh770.github.io/links/<כינוי>`), כדי שיהיה נוח
לשתף אותה.

## קוד QR
לצד כפתור ההעתקה יש כפתור "QR" שמציג ברשומה עצמה תמונת קוד QR לקישור
המקוצר, כדי שאפשר יהיה לסרוק אותו ישירות (למשל מפלייר או מסך). התמונה
נוצרת דרך שירות חיצוני חינמי וללא הרשמה
([api.qrserver.com](https://goqr.me/api/)) - לא נשמר שום דבר, רק תמונה
שנטענת לפי דרישה בלחיצה.

## זמן עדכון
אחרי שמירה ב-admin.html, ייתכן שיעברו דקה-שתיים עד שהשינוי יופיע בפועל
בכתובת הציבורית - זהו זמן הפריסה (deploy) הרגיל של GitHub Pages, לא
תקלה. הממשק מציג הודעה על כך אחרי כל שמירה.

## קטלוג ציבורי (משולב ב-`index.html`)
דף הבית מציג את **כל** הקישורים במערכת - כינוי, כתובת יעד, וכפתורי
פתיחה/העתקה לשניהם, עם חיפוש חופשי. בניגוד ל-`admin.html`, זה
**פתוח לכל אחד בלי טוקן** - כל מי שמגיע לדף הבית (`/`) רואה את כל
הרשימה.

**חשוב להבין:** מכיוון ש-`links.json` ממילא ציבורי (ראה "ביקורת אבטחה"
למעלה), הדף הזה לא חושף יותר מידע ממה שכבר אפשר היה למשוך ישירות מהקובץ -
אבל הוא הופך את זה להרבה יותר **נגיש ונוח לקריאה** לכל מבקר מזדמן, לא
רק למי שיודע לפנות לקובץ ה-JSON. אם אתה רוצה שקישורים מסוימים יישארו
בפועל לא-ידועים לרוב האנשים, שקול לא להוסיף אותם בכלל לקטלוג הזה (אין
כרגע דרך לסמן קישור כ"מוסתר מהקטלוג" - כל מה שב-`links.json` מוצג).

כן מוגן חלקית: קישור עם סיסמה מוצג בקטלוג עם "🔒 מוגן בסיסמה" **במקום**
כתובת היעד בפועל, וכפתורי "פתח יעד"/"העתק יעד" לא מוצגים לו - כדי לא
לעקוף את ההגנה שהגדרת. עדיין אפשר ללחוץ על "פתח קישור" (הקישור המקוצר
עצמו), וזה יבקש סיסמה כרגיל דרך `404.html`.

## תכונה עתידית: הגבלה לפי מדינה
נשקלה תכונה שמגבילה קישור למדינות מסוימות בלבד (לפי זיהוי IP), אך היא
הוסרה בינתיים. אם תתווסף בעתיד, עדיף שתהיה עם תפריט בחירת מדינות
(checkbox / multi-select) ולא הקלדת קודים ידנית.

## ביקורת אבטחה - ממצאים

### תוקן: XSS דרך הכינוי (חמור)
`404.html` הציג את הכינוי (מה-URL) בתוך הודעות "לא נמצא"/"פג תוקף" בלי
לנקות אותו - כינוי שמכיל HTML/JS זדוני (למשל תוך שימוש בקישור עם
`<img src=x onerror=...>` בתור הכינוי) היה מתבצע בדפדפן של **כל מבקר**
שלוחץ על קישור כזה, כולל גישה ל-localStorage של האתר (שם שמור טוקן
הניהול, אם המנהל התחבר אי-פעם באותו דפדפן). זו הייתה נקודת התקפה
קלאסית ל-phishing ממוקד. **תוקן** - כל ערך דינמי עובר עכשיו ניקוי HTML
(`escapeHtml`) לפני הצגה, גם ב-`404.html` וגם ב-`admin.html`.

### תוקן: הזרקת קוד דרך שדות עריכה בממשק הניהול
כינוי או כתובת יעד עם תו גרש (`'`) היו יכולים "לשבור" את קוד ה-JS
שנבנה בתוך `onclick="..."` ולהריץ קוד שרירותי בעמוד הניהול עצמו - שם
הטוקן זמין. **תוקן** - נוסף ניקוי ייעודי (`attrJs`/`attrHtml`) לכל
מקום שמזריק ערך דינמי ל-HTML, וגם ולידציה שמגבילה כינוי חדש לאותיות
אנגליות/ספרות/מקף/קו-תחתון בלבד.

### מגבלה מובנית (לא ניתנת לתיקון באדריכלות הזו): links.json ציבורי
כל תוכן `links.json` - כולל כתובות היעד, ה-hash של הסיסמאות, ותאריכי
היצירה - נגיש לכל אחד שיפנה ישירות לכתובת הקובץ בריפו, גם אם הכינוי
עצמו "לא ידוע". אל תסמוך על כינוי לא-מנוחש כהגנה על תוכן רגיש, ואל
תשתמש בשירות הזה לקישורים שהיעד שלהם צריך להישאר סודי.

### מגבלה מובנית: אפשרות DoS על הגבלת כניסות
ספירת הקליקים מבוססת על שירות חיצוני ציבורי, ללא הרשאה - כל מי שיודע
(או מנחש) את `COUNTER_PREFIX + כינוי` (שניהם גלויים בקוד המקור הפומבי)
יכול לשלוח בקשות "hit" ישירות מבלי לעבור דרך הקישור בפועל, ובכך "לצרוך"
מראש את מכסת ה-`maxClicks` ולגרום לקישור להיראות "פג תוקף" באופן מלאכותי.
מומלץ לא להסתמך על הגבלת כניסות למטרות קריטיות.

### מגבלה מובנית: סיסמת קישור היא הגנה רכה
כבר תועד למעלה - ה-hash גלוי בקובץ ציבורי וניתן לפיצוח offline בלי
הגבלת ניסיונות. לא מיועד להגנה על תוכן רגיש באמת.

### המלצה: תוקף לטוקן
מומלץ להגדיר לטוקן ה-GitHub תאריך תפוגה (Expiration) בעת היצירה, ולא
"ללא תפוגה" - כך שאם הוא דולף בכל זאת, החשיפה מוגבלת בזמן.

### תוקן (סבב נוסף): תצוגת קישור שגויה עם דומיין מותאם
תצוגת הקישור המקוצר בכל שורה בניהול עדיין השתמשה בקוד קשיח
`OWNER.github.io/REPO` במקום בזיהוי האוטומטי - כך שאחרי חיבור דומיין
מותאם, ההעתקה וה-QR היו עובדים נכון אבל **התצוגה** הייתה מראה כתובת
ישנה ומטעה. תוקן להשתמש באותו זיהוי אוטומטי בכל מקום.

### תוקן (סבב נוסף): שאילתת DOM שברירית
כמה פעולות (כמו הצגת QR) חיפשו אלמנט לפי סלקטור CSS שבנוי מהכינוי עצמו
(`#row-כינוי`) - אם כינוי (ישן, שנוצר לפני הגבלת התווים) מכיל תו מיוחד
בתחביר CSS, זה יכול לשבור בשקט. הוחלף בשיטת חיפוש שלא תלויה בתחביר
סלקטור.

## הקמה
הקבצים כבר מוגדרים עבור `sh770/links` - אין צריך לערוך שום דבר בקוד.

1. צור ריפו בשם `links` תחת החשבון `sh770` והעלה אליו את כל הקבצים
   (`links.json`, `404.html`, `admin.html`, `index.html`,
   `style.css`, `favicon.svg`, `favicon.ico`, `apple-touch-icon.png`).
2. הפעל GitHub Pages: Settings → Pages → Source: `main` branch, `/ (root)`.
3. זהו.

**נתיב הבסיס (`REPO_BASE` ב-`404.html`, וכתובת השיתוף ב-`admin.html`)
מזוהה אוטומטית** לפי הכתובת שבה הדף נטען בפועל - לא צריך לערוך את זה
ידנית, גם כשתחבר בהמשך דומיין מותאם (למשל דרך Cloudflare). ראה סעיף
"דומיין מותאם" למטה.

אם בעתיד תשנה את **שם הריפו עצמו** או תעביר אותו לחשבון GitHub אחר
(לא קשור לדומיין הציבורי) - יש לעדכן ב-`admin.html` את `OWNER` ו-`REPO`,
כי אלה נחוצים לקריאות ה-API של GitHub ולא ניתנים לזיהוי אוטומטי. אופציונלי:
`COUNTER_PREFIX` (זהה בשני הקבצים) - לא חובה לשנות, אבל אם אתה פותח ריפו
נוסף מאותה תבנית, כדאי קידומת שונה לכל ריפו.

## דומיין מותאם (למשל דרך Cloudflare)
בזכות הזיהוי האוטומטי של נתיב הבסיס, **אין צורך לערוך קוד** כשמחברים
דומיין מותאם. השלבים:
1. ב-GitHub: Settings → Pages → Custom domain → הזן את הדומיין (זה
   יוצר קובץ `CNAME` בריפו אוטומטית).
2. ב-Cloudflare (DNS): רשומת CNAME מהתת-דומיין (למשל `go`) אל
   `sh770.github.io`. מומלץ להשאיר "DNS only" (ענן אפור) עד שהתעודה
   של GitHub מונפקת בהצלחה, לפני שמפעילים proxy (ענן כתום). אם תפעיל
   proxy - יש להגדיר ב-Cloudflare SSL/TLS mode = **Full**, אחרת לולאת
   הפניות.
3. חזרה ב-GitHub: אחרי אימות ה-DNS, סמן "Enforce HTTPS".
4. אם מפעילים proxy של Cloudflare, כדאי Cache Rule שעוקף קאש (או TTL
   קצר) עבור `/links.json` - אחרת שינוי בקישור עלול "להיתקע" גם אחרי
   שה-GitHub Pages כבר עודכן.

## יצירת טוקן לניהול
כדי לנהל קישורים דרך `admin.html` צריך GitHub Personal Access Token עם
הרשאת כתיבה **לריפו הזה בלבד**:

1. GitHub → Settings → Developer settings → Personal access tokens →
   Fine-grained tokens → Generate new token.
2. **Token name** - שדה שם חופשי, רק לזיהוי שלך ברשימת הטוקנים - לא
   משפיע על אופן הפעולה. מומלץ שם ברור כמו `links-admin`, כדי שתדע
   בעתיד למה הטוקן הזה משמש אם תרצה למחוק או לחדש אותו.
3. Repository access: **Only select repositories** → בחר את הריפו הזה.
4. Permissions → Contents: **Read and write**.
5. צור את הטוקן ושמור אותו במקום בטוח (הוא מוצג פעם אחת בלבד).

## חשוב לגבי אבטחה
כל הקבצים בריפו (כולל קוד ה-HTML/JS) גלויים לציבור, גם אם תשתמש בסיסמה
בתוך הקוד — היא תהיה גלויה לכל מי שיסתכל ב-source. **לכן אין להטמיע את
הטוקן בקוד עצמו.** הדרך הבטוחה: להיכנס ל-`admin.html` ולהזין את הטוקן
ידנית בכל פעם (או פעם אחת — הוא נשמר רק ב-localStorage בדפדפן שלך, לא
נכתב לריפו). בלי טוקן תקין עם הרשאת כתיבה, GitHub עצמו יחסום כל ניסיון
עדכון — זו ההגנה האמיתית.

אם ברצונך רמת אבטחה גבוהה יותר (למשל שגם הצפייה בקישורים תהיה מוגנת),
זה דורש שרת אמיתי — הפתרון הזה מתאים לתרחיש של "רק אני יודע/ת את
הטוקן ומנהל/ת קישורים".

### לגבי קובץ `.env`
שים לב: הפרויקט הזה **לא** משתמש בקובץ `.env` בפועל, ולא יכול - זהו
אתר סטטי טהור בלי שלב build (npm/webpack/vite וכדומה), שרק דרכו קובץ
`.env` היה יכול "להיכנס" לקוד ה-JS שרץ בדפדפן. גם אם תיצור קובץ `.env`
ותוסיף אותו ל-`.gitignore` - הדפדפן פשוט לא יכול לקרוא אותו, ובכל מקרה
`.gitignore` מונע ממנו להיות חלק מהריפו שמפורסם ב-GitHub Pages. הגדרת
`.gitignore` בכללי היא הרגל טוב, אבל בפרויקט הספציפי הזה היא לא נחוצה
בשביל הטוקן - השיטה שכבר מיושמת (הזנת הטוקן ב-`admin.html`, שנשמר רק
ב-localStorage של הדפדפן) היא הדרך הנכונה כאן.
